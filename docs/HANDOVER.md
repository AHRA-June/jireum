## 2. 화면 흐름

```
결재판(홈)  ─탭→  지름 결의서  ─결재 상신→  심사 중(2.5초)  →  판정서
   │                                                            │
   └────────────── 결재 대장 ←───────────────────────────────────┘
                   (항목 탭 → 그 판정서 다시 열림)
```

- **홈**: 검정 결재판, 금박 "결재를 바랍니다", Team 자금집행팀 / Name 서명값
- **신청서**: 기안자 서명 + 5문항 + "위 금액을 영수(청구)합니다."
- **판정서**: 결재란(담당 사인 / 심사역 도장 / 지름신 도장) + 도장 애니메이션
- **결재 대장**: 최근 50건, 총 심사·승인·신청 총액 요약

## 3. 판정 로직 (전부 `src/rules/jireum-rules.json`)

점수·문구·규칙은 **코드에 하드코딩하지 않는다.** JSON만 고치면 동작이 바뀐다.

- 총점 100 = 가격(40) + 지름 빈도(30) + 숙려 기간(20) + 필요성(10)
- 70점↑ 승인 / 40~69 조건부 승인 / 40 미만 부결
- 특수 규칙 4종 (점수 무시, `specialRules` **배열 순서대로** 먼저 걸리는 것 적용):

| key | 조건 | 도장 |
|---|---|---|
| `over_limit` | `price>3000000` | 권한 초과 |
| `instant_approve` | `price<=10000 && frequency=='1번째'` | 즉시 승인 |
| `already_decided` | `frequency=='세지 않습니다' && deliberation=='이미 결제창입니다'` | 심사 무의미 |

`condition` 문법은 `field<=N`, `field=='값'`, `&&` 결합만 지원한다
(`src/engine/judge.ts`의 `evalCondition`, eval 미사용). 새 연산자가 필요하면 거기를 고칠 것.

**규칙을 추가할 때 주의**: 테스트는 규칙을 배열 인덱스가 아니라 `key`로 찾는다
(`specialRule('instant_approve')`). 이 방식을 유지할 것.

## 4. 빌드 · 배포

```bash
npm install
npm run dev          # 로컬 개발
npm test             # 판정 엔진 테스트
npm run build        # 웹 빌드 + jireumform.ait 생성
npx ait token add    # 콘솔 API 키 등록 (최초 1회)
npm run deploy       # 콘솔로 업로드
```

- `apps-in-toss.config.ts`의 `appName`(`jireumform`)은 콘솔 등록값과 **반드시 일치**해야 한다
- 서비스: `https://jireumform.web.tossmini.com`
- QR 테스트: `https://jireumform.private-web.tossmini.com`

> **API 키**: 대화 중 노출된 적이 있으니 콘솔에서 한 번 재발급할 것.
> 저장소·설정 파일 어디에도 저장되어 있지 않다.

## 5. 남은 일 / 알아둘 것

### 출시 후 반드시 확인
- [ ] **카톡 공유 미리보기** — 유일하게 검증 못 한 항목. 운영 도메인이 살아야 확인 가능하다.
  링크 미리보기 이미지는 `public/og/*.png`(승인·조건부·부결·심사무의미·권한초과 5종)이고,
  `src/toss/bridge.ts`가 **공개 운영 도메인일 때만** `ogImageUrl`을 넘긴다.
  QR 테스트 환경(`private-web`)은 외부에서 접근이 안 돼 이미지를 못 받아오므로, 그때는 일부러 생략한다
  (넘기면 미리보기 카드가 통째로 비어 버린다 — 실제로 겪은 문제).
  `ogImageUrl`은 토스 앱 Android 5.240.0 / iOS 5.239.0 이상에서만 동작하고, 미지원 시엔
  이미지 없이 링크만 가도록 폴백이 걸려 있다.
- [ ] 토스 웹뷰에서 **이미지 파일 직접 공유**(`navigator.share({files})`)가 되는지.
  되면 판정서 PNG가 사진으로 첨부돼 미리보기가 필요 없다. 안 되면 문구+링크만 간다.

### 챌린지 출품
- 8월 바이브코딩 챌린지 「하찮아도 괜찮아」, 출품 마감 **2026. 8. 26.(수)**
- 신청폼에 넣을 문구는 `docs/challenge-submission.md`에 작성해 둠
- 신청폼 appName은 콘솔 등록값(`jireumform`)과 **정확히 일치**해야 함
- 한줄 소개와 주제 연관성이 출품 적합성 판단 기준

### 검토 반려 대비
- 금지: 리워드성 표현. 금융 상품·대출 연상 표현은 패러디임이 명확한 선까지만
- 면책 문구("본 판정은 법적 효력이 없으며…")는 모든 화면 하단에 고정 노출 중 — 빼지 말 것

### 다듬으면 좋을 것 (급하지 않음)
- 문서번호를 랜덤 4자리 대신 **결재 대장 순번**으로 (`제2026-지름-0007호` = 올해 7번째 지름).
  현재는 `{year}`+랜덤이며, 연도는 심사 날짜에서 가져온다
- 고액 기준 300만 원(`over_limit`)은 실사용 보고 조정
- **앱 로고 미정** — 홈 결재판과 톤을 맞춘다면 검정 가죽 + 금박 "결재" 압인 방향

### 이미 처리한 함정들 (다시 건드리지 말 것)
- 결재란에 "전결" 같은 두 줄짜리 요소를 넣으면 그 칸만 높아져 표가 어긋난다
- 결재 대장은 문서번호가 겹쳐도 옛 기록을 덮지 않는다(직전 항목과 같을 때만 건너뜀)
- `robots.txt`는 전체 차단이되 `/og/`만 미리보기 크롤러에 허용 — 전체를 막으면 공유 이미지가 죽는다
- 판정서 제목은 360px 이하에서 폰트를 줄여 한 줄을 유지한다

  App.tsx                     화면 전환(phase) 관리

  screens/                    Home · Input · Reviewing · Verdict · History
  components/                 OptionGroup(선택지) · SignModal(서명)
  share/verdictImage.ts       판정서를 1080x1440 PNG로 그리는 캔버스 렌더러

디자인 기준은 미색 용지 + 이중 괘선 + 큰 도장 + 하단 "지름결의서 · 사기 전에 결재부터 받아보세요".
